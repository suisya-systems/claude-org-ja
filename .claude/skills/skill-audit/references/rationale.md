# skill-audit — 規律の由来

[`.claude/skills/skill-audit/SKILL.md`](../SKILL.md) と [`audit-checklist.md`](audit-checklist.md) から移した「なぜこの規律があるか」の記録。規律そのものは本文に残してあり、ここにあるのは由来だけ。手順を実行するために読む必要はない。

## 1. 発火の閾値と `org-*` の除外（Step 1）

- N=5（pending）/ M=20（work-skill 数）は既定値。実運用で重くなれば PR で調整する。
- `org-*` を数えないのは、ノイズ源が `org-delegate` の work-skill 検索であり、`org-*` の増減は検索ノイズに直接影響しないため。

## 2. 状態ベースで起動し、提案までに留める理由（トリガー経路）

- 時間ベースの `/loop` で起動しないのは、変化の無い日に raw ログを汚す副作用を避けるため。
- 自動で削除・統合・owner 追記をしないのは次の理由による:
  - 廃止の誤判断は `org-delegate` 側で「使える skill が無い」状態を生む（委譲精度の低下）
  - 統合は description・トリガ語・手順の擦り合わせを要し、機械的にはできない
  - owner 追記は人間確認が最も軽い運用で、ここだけ自動化しても効果が小さい

## 3. 判定しきい値（audit-checklist）

- **90 日**: 言及の観察窓。本プロジェクトの活動頻度で調整してよい。
- **50%**: トリガ語の重複率。厳しくし過ぎると偽陰性、緩すぎると偽陽性。
- **3 項目中 2 つ以上**: 統合判定の閾値。1 つでも該当なら候補にすると誤検出が増える。
