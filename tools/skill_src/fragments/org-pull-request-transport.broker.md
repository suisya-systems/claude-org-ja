> **輸送層 両系（`ORG_TRANSPORT`: 既定 `broker` / opt-in `renga`）**: 本スキルの `mcp__org-broker__*`（worker への修正指示 `send_message` 等）は **コード既定 `broker`** フレーム（`tools/transport.py: DEFAULT_TRANSPORT`、移行目標。下記「二フレーム注記」を先に参照）で書いてあり、tool 名はそのまま従えばよい。ただし **`CI_COMPLETED` / `PR_MERGED` 等が broker の push 一次**（各ペイン同居の channel sidecar `server:org-broker-channel` が `notifications/claude/channel` で窓口の idle セッションへ注入。runtime push-first 0.1.24+、設計 SoT は transport-lab `docs/design/broker-native-roles.md` §9）**で届くのは、pr-watch の peer 通知 helper `tools/peer_notify.py: notify_peer` が broker に解決したとき**で、`ORG_TRANSPORT` 無設定でも `tools/transport.py` の `resolve()` 経由でコード既定の `broker` に解決される（`ORG_TRANSPORT=renga` を明示した pane では renga に解決し、受信は renga の in-band push になる。下記の二フレーム注記と SKILL.md 2b-i 参照）。**push 失効時のフォールバックは送信 transport に依存**（broker に解決した場合は窓口がターン冒頭で能動 `mcp__org-broker__check_messages`、renga に解決した場合は broker キューに載らないため events テーブルのポーリングで受ける。SKILL.md 2b-i の受信モデル注記を参照。§9.6）、エラーは broker 拡張コード（[`.claude/skills/org-delegate/references/renga-error-codes.md`]({{ROOT}}.claude/skills/org-delegate/references/renga-error-codes.md) の broker 節）が加わる。`ORG_TRANSPORT=renga`（opt-in・切戻し可）では完全修飾名が **`mcp__org-broker__*` → `mcp__renga-peers__*`** に機械置換され、CI_COMPLETED 等は `<channel source="renga-peers">` の in-band push で届く（手順は同型・renga は削除せず常時有効な切戻しの安全装置）。詳細は CLAUDE.md「輸送層（transport）両系」節と [`docs/contracts/backend-interface-contract.md`]({{ROOT}}docs/contracts/backend-interface-contract.md) Surface 8（ratified 2026-06-14。push 一次への additive 改訂 S3 が ratified 済み（2026-06-15）・既存 ratified 本文不変更）を参照。

> **「既定」の二フレーム注記（Refs #604）**: 本スキルが `mcp__org-broker__*` 一次で「既定 `broker`」と書くのは**コード既定**フレーム（`tools/transport.py: DEFAULT_TRANSPORT` が runtime 0.1.28 / Epic #586 で `broker` にフリップ済み・移行目標）。**運用既定は renga**（broker 実走 dogfood は Epic #6 Issue G まで未活性）で、root `CLAUDE.md`「輸送層（transport）両系」節と同じ二フレーム関係にある。**重要（pr-watch peer 通知の実挙動）**: pr-watch が CI 完了 / merge / タイムアウト時に Secretary へ送る peer 通知 helper `tools/peer_notify.py: notify_peer` は `tools/transport.py` の `resolve()` 経由で transport を決める（Refs #941。かつての raw env 判定は解消済みで、`tools/peer_notify.py` の `_resolve_transport` が根拠）。`ORG_TRANSPORT` 無設定ならコード既定の `broker` に解決して broker CLI（`claude-org-runtime broker send`）経路、`ORG_TRANSPORT=renga` 明示時は renga / `RENGA_SOCKET` 経路（`RENGA_SOCKET` も無ければ silent no-op）に乗る。raw env 分岐が残るのは runtime 未インストール等で `resolve()` が使えない場合の never-raise フォールバックだけである。したがって無設定環境でも `CI_COMPLETED` 等は broker channel sidecar の push 一次で届き、renga の in-band `<channel source="renga-peers">` push で届くのは `ORG_TRANSPORT=renga` を明示した pane である（SKILL.md 2b-i は両系を併記する）。
